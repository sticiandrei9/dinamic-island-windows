# v0.2.0 · D. Aplicația — Plan de implementare

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** setări persistente + fereastră de setări, insule pe mai multe monitoare cu mărime configurabilă, log în fișier și update-uri descărcate automat dar aplicate la cerere (tray, insulă) sau la următoarea pornire.

**Spec:** `docs/superpowers/specs/2026-10-14-v020-d-app-design.md` (+ `…-v020-overview.md`)

**Tech:** Tauri 2, `tauri-plugin-log` 2, `tauri-plugin-notification` 2, `tauri-plugin-updater` 2 (deja), Node `node:test`.

## Global Constraints
- Toate textele vizibile sunt în română.
- Fiecare setare are `#[serde(default)]`; fișierul corupt e redenumit `settings.corrupt.json`.
- Scara pentru mărime: small 0.85 / normal 1 / large 1.15; fereastra insulei e 520·s × 300·s.
- Verificarea de update: la 30 s după pornire, apoi la 6 h; timeout 120 s; la pornire timeout 20 s.
- Nu se loghează titluri de piese, titluri de ferestre sau texte de notificări.
- Rust: `export PATH="$HOME/.cargo/bin:$PATH"`; teste `cd src-tauri && cargo test`, `npm test`.

## Review Focus
1. `settings.json` corupt sau dintr-o versiune viitoare cu câmpuri necunoscute → aplicația pornește cu ce se poate citi; câmpurile necunoscute sunt ignorate.
2. Monitorul ales e deconectat → insula apare pe cel principal și revine când monitorul revine.
3. Update descărcat, apoi o versiune și mai nouă publicată → se descarcă cea nouă, iar fișierul vechi e șters.
4. Pornire fără rețea cu update în așteptare → pornirea nu se blochează mai mult de 20 s și insula apare.
5. Fereastra de setări deschisă de două ori → o singură fereastră, adusă în față.

### Task D1: `settings.rs`, setări persistente
**Files:** create `src-tauri/src/settings.rs`; modify `main.rs`.
**Produces:** `Settings` (serde, Clone, PartialEq), `Modules`, `ExpandOn`, `MonitorChoice` (string: "primary" | "all" | device name), `Size`; `Settings::load(path) -> (Settings, LoadNote)`, `Settings::save(&self, path) -> io::Result<()>` (atomic: tmp + rename); `scale(size) -> f64`; managed state `SettingsState(Mutex<Settings>, PathBuf)`; comenzile `get_settings`, `set_settings(settings)` → salvează și emite `settings-changed` cu setările.
**Tests:** `implicit_toate_modulele_pornite`, `json_partial_completat_cu_implicite`, `campuri_necunoscute_ignorate`, `json_corupt_recuperat_si_redenumit` (temp dir), `salvare_atomica_si_recitire`, `scara_marimi`.

### Task D2: log în fișier
**Files:** `Cargo.toml` (`tauri-plugin-log = "2"`, `log = "0.4"`), `main.rs`, `updater.rs`, `media.rs`.
Plugin cu target `LogDir { file_name: Some("dynamic-island") }`, `max_file_size(1_000_000)`, `RotationStrategy::KeepOne`, nivel Info (Debug în debug). Toate `eprintln!` → `log::warn!`. Log la pornire: `Dynamic Island <versiune> pornit`. Comandă `open_log_dir`.
**Verify:** după rulare, `%LOCALAPPDATA%\ro.andrei.dynamicisland\logs\dynamic-island.log` conține linia de pornire.

### Task D3: monitoare + mărime + ferestre create din Rust
**Files:** create `src-tauri/src/displays.rs`; modify `tauri.conf.json` (fără `windows`), `main.rs`, `hittest.rs`, `platform.rs`, `src/island.js`, `src/styles.css`.
**Produces:** `MonitorInfo { name, x, y, width, height, scale, primary }`; funcția pură `target_monitors(choice, &[MonitorInfo]) -> Vec<MonitorInfo>`; `sync_windows(app)` (creează/închide/repoziționează `island-<i>`); thread la 5 s + la `settings-changed`. Hit-test: `IslandRects(Mutex<HashMap<String, Rect>>)`; `set_island_rect` folosește `WebviewWindow` label; un singur thread verifică toate ferestrele; `island-hover` cu `emit_to(label)`. JS: aplică `zoom` pe `#stage` din setări (`get_settings` + `settings-changed`), iar dreptunghiul raportat rămâne în coordonate logice (Rust înmulțește cu scara).
**Tests:** `principal_implicit`, `toate_monitoarele`, `monitor_anume`, `monitor_disparut_cade_pe_principal`, `fara_principal_ia_primul`; JS `sizeScale`.

### Task D4: updater cu descărcare + aplicare la cerere
**Files:** rescrie `src-tauri/src/updater.rs`; `Cargo.toml` (`tauri-plugin-notification = "2"`); `capabilities` dacă e nevoie.
**Produces:** `UpdateState` (`Idle | Checking | UpToDate{checked_at} | Downloading{version} | Ready{version} | Error{msg}`), serializat; funcțiile pure `next_state(state, event) -> state` și `pending_action(pending: Option<Pending>, current, remote: Option<String>) -> PendingAction { Install, Discard, Keep }`; comenzile `get_update_state`, `check_updates_now`, `apply_update`; evenimentul `update-state`; descărcarea în `app_cache_dir/updates/` + `pending.json`; instalarea la pornire (înainte de crearea ferestrelor, timeout 20 s); notificare Windows la `Ready`.
**Tests:** tranziții `next_state`; `pending_action` (mai nouă + server confirmă → Install; versiune ≤ curentă → Discard; server indisponibil → Keep; server are altă versiune → Discard).

### Task D5: tray nou
**Files:** `tray.rs`. Meniu: `Dynamic Island <v>` (dezactivat), `Aplică update v… / Verifică actualizări`, separator, `Setări…`, `Pornește cu Windows`, separator, `Ieșire`. Eticheta se actualizează la `update-state`. „Setări…” deschide/aduce în față fereastra `settings`. Comutatorul de autostart sincronizează `settings.autostart`.

### Task D6: fereastra de setări
**Files:** create `src/settings.html`, `src/settings.css`, `src/settings.js`; `src/lib/settings-ui.js` (funcții pure: `formatLastCheck(state, now)`, `monitorLabel(m)`), `tests/settings-ui.test.js`.
Stil macOS System Settings, temă după sistem; secțiunile din spec; orice schimbare → `set_settings`; stare update live din `update-state`; butoane „Verifică acum”, „Aplică”, „Deschide folderul cu log-uri”. Comandă `list_monitors`.
**Tests:** `formatLastCheck` (acum / acum 5 minute / acum 2 ore / eroare / gata), `monitorLabel`.

### Task D7: insula consumă setările + anunțul de update
**Files:** `src/island.js`, `src/styles.css`, `src/index.html`.
`expand_on: "click"` → hover nu mai extinde; modulul `apps` oprit → rândul de aplicații ascuns; modulul `media` oprit → insula ignoră `media-update`. Anunțul `Ready` reutilizează `#update` („Actualizare disponibilă v…”, 4 s) până la cadrul de activități din B. Rândul „v… disponibilă · Aplică” în extins.
