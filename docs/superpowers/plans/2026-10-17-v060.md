# v0.6.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Vizualizator după sunetul real, centru de control în fila Acasă, starea CI/deploy (GitHub Actions + Cloudflare) și bateriile Bluetooth, livrate ca v0.6.0.

**Architecture:** Ca la v0.5.0: fiecare funcție e un modul Rust în `src-tauri/src/` cu thread propriu și logică pură testată, plus un view JS încărcat dinamic de `island.js`. Datele vin prin evenimente; comenzile Win32/WinRT rulează pe `spawn_blocking` sau pe thread-ul care deține fereastra.

**Tech Stack:** Rust (Tauri 2, `windows` 0.58, `serde_json`), JS ES modules, `node --test`, `cargo test`, `gh` CLI.

**Spec:** `docs/superpowers/specs/2026-10-17-v060-design.md`

## Global Constraints

- Regulile din `CLAUDE.md` („Hard-won rules”): fără `ShowWindow` direct pe insulă; fără `WS_EX_TOOLWINDOW` după creare; `windows` rămâne `0.58`; `WS_EX_NOACTIVATE` doar prin `platform::set_no_activate`; Win32 doar pe thread-ul care deține fereastra; după orice modificare în `src/` se recompilează înainte de test.
- `PATH` pentru Rust în Bash: `export PATH="$HOME/.cargo/bin:$PATH"`.
- Text UI doar prin `t()` / `data-i18n`, chei noi în `ro`, `en` **și** `ru`, aceiași parametri `{…}` (testul `tests/i18n.test.js`).
- Comentarii, commit-uri, docs în română; trailer exact `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- EOL-ul fiecărui fișier păstrat (`git ls-files --eol`); niciodată `sed -i` pe fișiere CRLF; liniile cu `\n`/`\\` cu Edit.
- Module noi: `visualizer` (pornit), `controls` (pornit), `ci` (**oprit**), `batteries` (pornit). Setări noi: `cloudflare_token: String`, `cloudflare_account: String` (goale).
- Vizualizator: 5 benzi, ~30 cadre/s, doar cât există media `playing` și o insulă vizibilă; tăcere > 1 s → un singur `[0;5]`, apoi nimic.
- Centru de control: 8 butoane, ordinea Wi-Fi, Bluetooth, mod întunecat, lumină de noapte, Nu deranja, microfon, blocare, sleep; sleep cere al doilea click în 3 s; o comandă indisponibilă ascunde butonul.
- CI: ritm 30 s cât rulează ceva, altfel 60 s; repo-uri `affiliation=owner` cu push în ultimele 7 zile, lista la 2 min; plafon 1000 apeluri/oră; tranzitorie la final 5 s, click deschide `url` (doar https). Tokenul Cloudflare niciodată în log.
- Niciun `npm run release`, push sau acțiune care schimbă starea PC-ului lui Andrei (Wi-Fi, Bluetooth, temă, sleep, blocare) fără acordul lui; testele automate nu apelează niciodată comenzile care schimbă starea.
- Verificarea pe PC se face o singură dată, la final (Task 9), dintr-un build release copiat în `%LOCALAPPDATA%\Dynamic Island Test\`.

## Review Focus

1. **Captura loopback când dispozitivul implicit se schimbă sau dispare (căști deconectate)** → thread-ul reface captura, nu cade și nu blochează; test pur pe decizia de refacere în Task 2 (`refacere_la_schimbarea_dispozitivului`).
2. **`gh` lipsă, neautentificat sau care întoarce JSON neașteptat** → modulul `ci` nu cade, Setările arată motivul; test în Task 6 (`gh_raspunsuri_ciudate`).
3. **Pornirea modulului CI cu istoric vechi** → nicio rafală de bule; o rulare terminată după pornire tot apare; test în Task 6 (`fara_rafala_la_pornire`, `rulare_scurta_intre_verificari`).
4. **Fila Acasă cu muzică + calendar + Claude + baterii** → conținutul se derulează, insula nu trece de 330 px, click-urile pe butoane merg; verificare în Task 8 și Task 9.
5. **Blob-ul luminii de noapte într-un format necunoscut** → butonul lipsește, nu se scrie nimic; test în Task 4 (`format_necunoscut_nu_se_scrie`).
